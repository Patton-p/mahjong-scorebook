# 血战账本 · 原生微信小程序

5位玩家，默认「日落尤…、轩逸、在西…、机器人、机器人2」。一张照片核对并保存后记一局；不识别游戏局数，不计算累计截图差额。机器人无论输赢均不参与结算，各局按原网页算法独立加权，累计总分直接相加各局保存的整数分位。

## 已包含

- 原生WXML/WXSS/JS界面，积分总览、截图预览、4行识别结果映射到5名玩家、原始分手动修正、加权预览。
- 保存、撤销上一局、历史原始分和加权分、玩家/机器人设置、新开一场。
- 本机持久化、JSON备份/恢复、复制本场积分、分享小程序入口。
- 腾讯云高精度OCR云函数，服务端密钥和调用者白名单。图片通过云函数转发OCR，项目代码不保存图片、不输出识别内容日志。

## 1. 先运行手动记账（无需服务器或WxJava）

1. 下载仓库，在微信开发者工具选择「导入项目」，目录选择本文件所在的 `wechat-miniapp` 文件夹（下载独立代码包时是 `mahjong-miniapp`）。
2. 填入你的小程序AppID；配置里的 `touristappid` 仅作占位，支持情况取决于开发者工具。使用自己的AppID才能完整真机预览及云开发。
3. 编译后直接录入5人原始积分，正数为赢、负数为输，合计必须为0。设置机器人后查看预览并保存。
4. 在工具中点击「预览」，用已授权开发者/体验成员的微信扫码。正式公开使用仍需小程序后台配置、上传代码、审核发布。

## 2. 启用截图自动识别

1. 开通微信云开发，创建环境，将环境ID填入 `miniprogram/config.js` 的 `cloudEnv`。
2. 在腾讯云开通文字识别OCR服务，创建有 `ocr:GeneralAccurateOCR` 权限的密钥。额度及价格以腾讯云控制台为准。
3. 在开发者工具中，右键 `cloudfunctions/ocr` → 上传并部署：云端安装依赖。配置函数超时至少45秒、内存256MB或以上（按实际运行需求调整）。
4. 仅在云函数环境变量配置以下值，切勿把密钥写进前端、备份或GitHub：

| 环境变量 | 内容 |
|---|---|
| `OCR_SECRET_ID` | 腾讯云密钥SecretId |
| `OCR_SECRET_KEY` | 腾讯云密钥SecretKey |
| `OCR_REGION` | 可选，默认ap-guangzhou |
| `OCR_ALLOWED_OPENIDS` | 允许调用OCR的微信用户OpenID，多个用英文逗号分隔 |

5. 首次选择图片并点击云端识别后，若未在白名单，小程序会复制你自己的OpenID。把它加入 `OCR_ALLOWED_OPENIDS`，重新部署/生效配置后再试。空白名单会拒绝所有OCR请求，不消耗OCR接口额度。
6. 选择结算截图 → 云端识别 → 核对四行昵称、原始积分和正负号 → 选择四位不同玩家 → 填入表单 → 检查加权预览 → 保存。第五位默认0；只有保存成功才增加一局。
7. 云端识别发送的是完整所选图片，使用前请裁掉无关私人信息。当前限制图片约2MB，过大需裁剪压缩。OCR供应商的服务处理及留存以其条款为准。

## 3. 正式发布前

- 使用真实AppID、配置小程序后台「用户隐私保护指引」，如实说明相册/拍照选图以及腾讯云OCR处理；代码调用了 `wx.requirePrivacyAuthorize`，运行时授权不能替代后台声明。
- 用真机分别检查相册、拍照、隐私授权拒绝、断网、OCR额度不足、OCR四行识别及手动修正、备份恢复。当前交付只完成Node自动测试和静态检查，尚未在你的微信AppID下真机验收。
- 私人使用可保留白名单；若计划面向公众开放OCR，应先加每用户限流、总额度上限和监控，再扩大白名单。不要直接删掉调用者限制。
- 选择与用途相符的服务类目，上传代码并提交审核，审核通过后发布。GitHub Pages不能直接托管原生小程序。

## 数据和算法

记录仅在当前设备本机存储，不会因分享小程序而同步。未保存截图/原始OCR全文；历史记录保存原始分、加权整数分位、机器人名单、备注和时间。修改机器人设置只影响新局；修改玩家名单需先新开一场，避免把历史分数归给别人。备份仅支持本小程序自己的格式，不直接导入旧网页备份。

W=真人赢分总额，L=真人输分绝对值总额，P=min(W,L)。赢家按P×个人赢分/W，输家按-P×个人输分绝对值/L分配，精确到0.01分，最大余数法补齐尾差；只有赢或只有输时结算为0。

参考例：[38,9,-23,-24,0] → [18.60,4.40,-23.00,0,0]；[-10,20,-40,15,15] → [-4.00,20.00,-16.00,0,0]；总分[14.60,24.40,-39.00,0,0]。

OCR解析按文字行坐标提取建议值，不能保证所有截图版式正确；所有结果均需手动核对。连续累计战绩图按图片完整分数逐局入账，会造成重复计分，应使用单局结算图。

## 开发与验证

本目录运行 `npm test`（Node 18+），覆盖算法参考样例、5000组随机守恒/机器人排除、尾差、备份校验、OCR坐标提取。云函数依赖需由云端安装。

当前采用微信云开发Node云函数，不需要WxJava。以后如需公众号/小程序账户体系、订单支付或Java业务后台，可独立增加WxJava服务。
